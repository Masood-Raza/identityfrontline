Automate User Lifecycle
Build Your First n8n Workflow for IAM

Create a user in Active Directory and watch everything happen automatically — Entra ID sync, welcome email, Teams notification, manager approval, and audit log. Your first IAM automation, powered by n8n. Free.

MR
Syed Masood RazaIAM Architect · AI + Security Automation · Fortune 500 SME

In enterprise IAM, the most time-consuming work is not configuring SSO or writing Conditional Access policies. It is the daily grind of user lifecycle management — Joiner, Mover, Leaver. Accounts created, access adjusted, accounts disabled. Thousands of times per month.

Across the organisations I have worked with, the same pattern holds every time: once these automations are in place, the volume of tickets reaching IT support drops sharply. Bulk provisioning, group changes, password resets, access requests — work that used to sit in an analyst's queue gets resolved automatically, and the team is freed up for the problems that genuinely need a human.

The tool that makes this possible? n8n — a free, open-source workflow automation platform that connects to anything with an API. And in this guide, you are going to build your first n8n IAM workflow in your homelab.

By the end of this guide, you will have:

  • n8n installed and running in your homelab (free, self-hosted)
  • A workflow that triggers when a new user is created in Active Directory
  • Automatic welcome email sent to the new user
  • Teams/Slack notification to the IT team
  • Audit log entry recorded for compliance
  • A portfolio project that proves you can automate IAM operations
Prerequisites

You need the working homelab from Post 2 — Active Directory and Entra ID. Basic familiarity with PowerShell. No prior automation experience needed.

Why This Matters

The Joiner-Mover-Leaver Problem

Every organisation with employees faces the same challenge. People join, change roles, and leave. Each event triggers a cascade of identity actions:

Joiner-Mover-Leaver Lifecycle
Joiner
Create account
Assign groups
Provision access
→
Mover
Change department
Update groups
Adjust permissions
→
Leaver
Disable account
Revoke access
Archive data

When this is manual, mistakes happen. Accounts are created without the right groups. Leavers retain access for weeks. Movers accumulate permissions from every role they have held. These are not just inefficiencies — they are security vulnerabilities that auditors flag and attackers exploit.

Automation solves this. And n8n is how you build it.

What Is n8n

n8n — The Automation Platform IAM Teams Need

n8n (pronounced "n-eight-n") is a free, open-source workflow automation platform. Think of it as a visual programming tool where you connect nodes — each node performs an action like calling an API, sending an email, querying a database, or running a script. You drag, drop, and connect. No traditional coding required.

Why n8n over Power Automate or Logic Apps?

  • Free and self-hosted — no licence costs, no per-execution charges. You own the data.
  • 400+ integrations — Microsoft Graph, Active Directory (via LDAP), SMTP, Slack, Teams, ServiceNow, Jira, and hundreds more
  • AI-native — built-in nodes for OpenAI, Anthropic Claude, and other LLMs. You can add AI decision-making to any workflow.
  • Enterprise-ready — webhooks, error handling, retry logic, credential management, execution logs
  • Resume gold — showing n8n on your resume signals that you understand modern automation, not just legacy scripting
Phase 1

Install n8n in Your Homelab

You have two options: run n8n in the cloud (free tier) or self-host it. For a homelab, I recommend the cloud option — it takes 2 minutes and requires no Docker setup.

Option A: n8n Cloud (Recommended for Beginners)

StepAction
1Go to n8n.io and click Get started free
2Create an account with your email
3You get a free instance with 5 active workflows — more than enough for this lab

Option B: Self-Hosted via Docker (Advanced)

If you have Docker installed on your machine or a separate VM:

Install n8n with Docker
docker run -d --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n

Then open http://localhost:5678 in your browser. n8n is running.

Phase 2

Build the "New User" Detection Workflow

The first step in any automation is: what triggers it? In production, a new user in the HRIS (like Workday or BambooHR) triggers the Joiner workflow. In your homelab, we will use a PowerShell script that detects new AD users and sends a webhook to n8n.

Create the Webhook Trigger in n8n

StepAction
1In n8n, click New Workflow
2Name it: IAM - New User Onboarding
3Add a Webhook node (search for "Webhook" in the node panel)
4Set HTTP Method to POST
5Copy the Test URL — you will need this in the PowerShell script

Create the PowerShell Trigger Script

On your Domain Controller (DC01), create this script that monitors AD for new users and sends their details to n8n:

Monitor-NewUsers.ps1
# Monitor AD for new users and trigger n8n workflow $webhookUrl = "YOUR_N8N_WEBHOOK_URL_HERE" $checkInterval = 60 # seconds $lastCheck = (Get-Date).AddMinutes(-5) Write-Host "Monitoring for new AD users..." -ForegroundColor Cyan while ($true) { $newUsers = Get-ADUser -Filter { whenCreated -ge $lastCheck } -Properties whenCreated, Title, Department, EmailAddress, Manager foreach ($user in $newUsers) { $payload = @{ samAccountName = $user.SamAccountName displayName = $user.Name email = $user.UserPrincipalName title = $user.Title department = $user.Department createdAt = $user.whenCreated.ToString("o") } | ConvertTo-Json Invoke-RestMethod -Uri $webhookUrl ` -Method POST ` -Body $payload ` -ContentType "application/json" Write-Host "Triggered workflow for: $($user.Name)" ` -ForegroundColor Green } $lastCheck = Get-Date Start-Sleep -Seconds $checkInterval }
What this script does

Every 60 seconds, it checks Active Directory for users created since the last check. When it finds one, it sends their details (name, email, title, department) to your n8n webhook as a JSON payload. n8n takes over from there.

Phase 3

Build the Onboarding Workflow in n8n

Now build the automation chain. Each node performs one action, and they execute in sequence. Here is the complete workflow:

n8n Workflow — New User Onboarding
Webhook
Receives user
data from AD
→
Set Fields
Format data
for downstream
→
Email
Welcome email
to new user
→
Teams/Slack
Notify IT team
of new hire
→
Log
Audit entry
for compliance

Node 1: Set Fields (Data Transformation)

StepAction
1Add a Set node after the Webhook
2Map the incoming fields: displayName, email, title, department, createdAt
3Add a computed field: welcomeMessage = "Welcome to IAMLAB, " + displayName + "!"

Node 2: Send Welcome Email

StepAction
1Add an Email Send node (or Gmail / Microsoft Outlook node)
2Configure SMTP credentials (Gmail app password works for a lab)
3To: {{ $json.email }}
4Subject: Welcome to IAMLAB - Your Account is Ready
5Body: Use the template below
Welcome Email Template (HTML)
<h2>Welcome to IAMLAB, {{ $json.displayName }}!</h2> <p>Your account has been created.</p> <ul> <li><b>Username:</b> {{ $json.samAccountName }}</li> <li><b>Email:</b> {{ $json.email }}</li> <li><b>Title:</b> {{ $json.title }}</li> <li><b>Department:</b> {{ $json.department }}</li> </ul> <p>Next steps:</p> <ol> <li>Set up MFA at <a href="https://aka.ms/mfasetup">aka.ms/mfasetup</a></li> <li>Access your apps at <a href="https://myapps.microsoft.com">myapps.microsoft.com</a></li> </ol>

Node 3: Teams/Slack Notification

StepAction
1Add a Slack node (or Microsoft Teams node)
2Connect your Slack workspace or Teams channel via OAuth
3Channel: #iam-notifications
4Message: New user onboarded: {{ $json.displayName }} ({{ $json.title }}, {{ $json.department }}) - Account created at {{ $json.createdAt }}

Node 4: Audit Log

StepAction
1Add a Google Sheets node (or Spreadsheet File node for local logging)
2Create a Google Sheet called IAM Audit Log with columns: Timestamp, Action, User, Title, Department, Status
3Map: Timestamp = {{ $now }}, Action = USER_CREATED, User = {{ $json.displayName }}, Status = COMPLETED
What you just built

A complete onboarding automation: AD detects a new user → n8n receives the event → welcome email sent → IT team notified → audit log recorded. Five steps that used to require a human analyst now happen in under 10 seconds.

Phase 5

Level Up — Add an AI Decision Layer

Here is where your workflow becomes truly enterprise-grade. Add an AI node that evaluates each new user and makes intelligent decisions.

StepAction
1Add an OpenAI node (or Anthropic node) after the Set Fields node
2Connect your API key (OpenAI free tier gives you limited calls; enough for a lab)
3Use this prompt:
AI Prompt for Group Assignment
You are an IAM automation assistant. Based on the new user's title and department, recommend which Active Directory security groups they should be added to. User: {{ $json.displayName }} Title: {{ $json.title }} Department: {{ $json.department }} Available groups: - SG-IAM-Admins (IAM team only) - SG-Cloud-Admins (cloud infrastructure) - SG-Helpdesk (L1 support) - SG-VPN-Users (remote access) - SG-MFA-Enforced (all users) Respond with ONLY a JSON array of group names. Example: ["SG-VPN-Users", "SG-MFA-Enforced"]

The AI evaluates the user's title and department and recommends the right security groups. In production, you would add an approval step before the groups are actually assigned. In your lab, this demonstrates that you understand how AI-powered IAM automation works — and that is a conversation-changing skill in interviews.

Why this matters for your career

The combination of IAM + n8n + AI is extremely rare. Most IAM professionals know PowerShell. Almost none know n8n. Even fewer can integrate AI into identity workflows. This single lab project puts you in a category that most hiring managers have never seen in a candidate.

Phase 6

Document for Your Portfolio

  • Export your n8n workflow — n8n lets you export workflows as JSON. Save it to your GitHub repo alongside your PowerShell scripts from Post 2.
  • Screenshot the workflow canvas — the visual node graph is impressive in a portfolio. Annotate it with brief descriptions of each node.
  • Screenshot the execution log — show a successful end-to-end run with timing data.
  • Record a demo — create a user in AD, then show the email, Slack notification, and audit log appearing automatically. A 60-second screen recording is worth more than 10 pages of documentation.
  • Write the business case — "This workflow automates onboarding notifications that previously required manual L1 tickets. At scale, this reduces average onboarding time from 4 hours to under 10 minutes."
“I automated the Joiner-Mover-Leaver process using n8n workflows integrated with Active Directory and Entra ID, with an AI decision layer for group assignment.” — That is not a junior’s resume. That is an IAM automation architect’s resume.

What to Build Next

  • Leaver workflow — detect disabled accounts in AD and trigger offboarding: revoke access, notify manager, archive mailbox, log for compliance
  • Mover workflow — detect department changes and automatically update security group memberships
  • Access request portal — build a simple web form that submits access requests to n8n, routes for approval, and provisions automatically
  • Scheduled compliance report — n8n runs nightly, queries Entra ID for stale accounts, excessive permissions, and MFA gaps, emails a summary to the IAM team
  • Connect to ServiceNow/Jira — auto-create tickets for each onboarding event, linking your IAM automation to ITSM
